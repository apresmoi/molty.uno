# website — agent guide

molty.uno: the landing page (`/`) plus the Starlight docs. Root `AGENTS.md` applies.
Standalone pnpm package, Node 22: `pnpm install && pnpm check && pnpm build` → `dist/`.
Never deploy or publish from here; nothing in this package does.

## Sources of truth

- **Site identity** (`SITE_URL`, `REPO_URL`, the three.js CDN pin): `src/config/site.mjs`, and
  only there. `REPO_URL` is a placeholder until the GitHub owner is decided; the check rejects
  `github.com/` anywhere else in `src/`.
- **Repo docs stay in the repo.** `src/config/docs.mjs` lists the synced files (`docs/*.md`,
  `device/creatures/*.md`, `CONTRIBUTING.md`); `scripts/sync-docs.mjs` turns them into
  `src/content/docs/repo/*.md` (gitignored, rebuilt by `dev`/`build`) with `slug` and `editUrl`
  frontmatter. Fix content in the source file, not the copy. Hand-written, website-only pages
  (introduction, flash a release, setup, connect an agent) live in `src/content/docs/`.
- **Firmware for /setup is staged, never committed.** `scripts/stage-firmware.mjs` writes ESP
  Web Tools manifests (one per `device/firmware/boards/**/board.json`) and the images into the
  gitignored `public/firmware/`: `--local` from `../../device/firmware/build/<board>/`, `--release` from
  the latest GitHub release (deploy-website does this), `--none` manifests only. Same origin
  on purpose: release assets have no CORS.
- **The creature engine is imported, never copied.** `@creatures` → `../../device/creatures/js`,
  `@molty-files` → `../../device/creatures/molty`, `@molty-catalog` → `../../device/console/src/catalog`
  (names + fluid thumbnails generated by `device/console/tools/thumbs.mjs`). three.js resolves to the
  CDN URL as an external (`astro.config.mjs`), like `device/console/vite.config.ts`.

## Ownership and composition

- `src/pages/` holds thin Astro routes composed from `src/layouts/` (`SiteLayout`,
  `ContentLayout`). No page `<style>` or runtime `<script>` (JSON-LD only).
- `src/components/Name/Name.tsx` is the component; `index.ts` has explicit named exports.
  Import another component through its barrel. Components are React; `.astro` lives only in
  pages, layouts and `src/integrations/{astro,starlight}/` adapters.
- `src/services/molty-stage/` is the only owner of the fluid runtime. `pageFluid.ts` glues one
  `@glyphcss/fluid` fluid (`glue: "document"`, one `<pre>`, the sim in a Vite-bundled Worker from `@glyphcss/fluid/worker?worker`) to
  the page and reads its targets from the DOM: `data-fluid-word` (a text target that condenses
  while on screen; `data-fluid-color`, `data-fluid-delay`, `data-fluid-tint`), `data-fluid-molty`
  (a square slot a Molty emerges in as a mesh target; comma list + `data-fluid-every` cycles),
  `data-fluid-quiet` / `data-fluid-pool` (zones). `moltyMesh.ts` keeps the cute kit +
  MoodEngine (`@creatures`) as the pose rig and hands glyphcss the posed triangles.
  `speedReader.ts` is `@glyphcss/fluid/reader` on the round screen (`shape: "circle"`).
  `FluidField` / `SpeedReader` mount them; nothing else imports `@creatures`, `glyphcss` or
  `@glyphcss/*`. 30 fps, ≤ 176 columns; `prefers-reduced-motion` draws settled stills.
- The page must read without the engine: headings keep their DOM text (transparent only
  under `html[data-fluid="live"]`), Molty slots show the catalog still until
  `html[data-fluid-moltys="live"]`.
- `src/features/<feature>/` holds copy and data (`home/content.ts`, `moltys/catalog.ts`).
  `src/hooks/` holds reusable React hooks. Features, services, hooks and config never import
  components.

## Styling

- `src/styles/tokens.css` is the only place for colours, fonts, sizes: black glass, dim braille,
  monospace. The only UI colour is the wordmark green; every other colour comes from a Molty's
  palette (via the fluid). Dark and light: light inverts the fluid layer (`--m-fluid-filter`,
  a plain `invert(1)`) into ink on paper, handing the page's own fluid colours over
  pre-inverted (`molty-stage/paper.ts`: hue kept, ≥ 3:1); device screens stay dark LCDs (the
  `Device` screen's backdrop undoes the invert, `[data-screen]` takes the dark tokens), so a
  Molty looks the same in both themes. Light text tokens hold AA (`scripts/tests/light-theme`).
  `ThemeToggle` shares Starlight's `starlight-theme` key.
- Components own CSS Modules. `global.css` imports tokens, base and layout only. Starlight's
  chrome is mapped in `src/integrations/starlight/starlight.css`.
- Static presentation belongs in CSS; inline styles only for runtime values.
- Layouts must not overflow horizontally at 390px; wide `<pre>` blocks scroll inside themselves.

## Verification

- `pnpm check` — architecture rules (`scripts/checks/architecture.mjs`: owners, barrels,
  layers, engine/three import boundary, single repo URL, colour/font tokens, cycles) + prettier
  (`pnpm format` fixes). No baselines or exemptions.
- `pnpm build && pnpm preview`, then `pnpm screens` (`e2e/screens.mjs`): screenshots to
  `e2e-out/` (gitignored), fails on page errors, 390px overflow, a page fluid (its `<pre>`)
  that does not render or move, Moltys that never load, or a gallery picker that does not drive its slot.
  Look at the screenshots.
- `pnpm og` regenerates `public/og.png` from the live page fluid (needs the preview running).
- `dist/llms.txt`, `llms-full.txt` and raw `docs/*.md` come from `scripts/generate-llms-txt.mjs`.
